## Problem and required behavior

The sidebar already exposes separate Argo, glider, and current-streamline checkboxes. The bottom bar's `OBSERVATIONS` action opens/closes the fleet drawer but also forces both marker layers on and displays an active state when either layer is on. Its current-layer props are unused. `OceanCanvas` renders current vectors whenever the selected scalar variable is `currents`, even when the streamline checkbox is off; `App` also forces streamlines on when that variable is selected. These controls currently disagree about what is visible.

Make each map overlay an independent, truthful on/off choice: current streamlines, Argo markers, and glider markers. Selecting the `currents` variable must select the scalar current-speed field without silently enabling streamlines; switching scalar variables must not silently change the overlay choice. Turning off streamlines must hide only vectors, even while the current-speed field is selected. Argo and glider switches must affect their own markers independently. Opening the observation fleet drawer must not change marker visibility, and closing it must not hide or enable markers. Its button state and accessible label should describe the drawer, not imply that all observations are visible. If a bottom-bar current control is present, it must reflect and update the same state as the sidebar switch. Prefer the smallest coherent UI change; preserve the existing login/register flow and visual style.

Respect confirmed dataset readiness and available variables. A dataset without usable current components must not show streamlines or leave a misleading active control. During a dataset transition, failed metadata fetch, or unavailable dataset, do not present stale vectors or an active-looking unavailable overlay. On recovery, restore only a still-supported user choice; never resurrect stale vectors from the previous dataset. Keep observation source mode (`REAL_LOCAL` versus `SYNTHETIC`) and existing marker selection behavior intact. Do not conflate absence of observations with a disabled current layer. No new backend API, synthetic fallback, or live external feed is needed.
