# Phase 01 acceptance checklist

Recorded before frontend implementation. Authority: handbook physical pp. 5, 8-11 and the user Phase 01 request. Phase 1 has no previous-phase gate.

1. **AC01 Source and entry audit:** inspect all existing files, all 14 PDF pages, DOCX content and diagrams, all seven PPTX slides and slide 6 workflow. Inventory code, dependencies, data, tests, documentation, applicable AGENTS.md and source hashes; preserve previous work.
2. **AC02 Complete mapping:** every roadmap row retains original order/title/classification; every supplemental requirement or vision claim has an owner phase and acceptance check or documented gap. Missing sections and conflicts are explicit.
3. **AC03 Reproducible setup:** React resolves to 18; compatible Vite/Tailwind configuration, exact dependency pins and lockfile; README PowerShell install/run instructions, environment example and ignore rules. Inspect actual runtime and official version documentation.
4. **AC04 Shell and scope:** header with truthful status, left controls, central future viewport, right inspector; handbook p. 9 component boundaries. No globe/backend/scientific implementation. Future controls disabled with explanations; no fabricated feed/count/score/performance claims.
5. **AC05 Build:** production frontend build exits 0 after locked clean install.
6. **AC06 Lint:** relevant frontend/config lint exits 0, no warnings.
7. **AC07 Responsive browser inspection:** open production app at desktop and narrow widths, inspect readable controls, no overlap or horizontal overflow. Save screenshots and actual dimensions.
8. **AC08 Accessibility and interaction:** verify keyboard navigation, visible focus, functional shell-only controls, labelled unavailable controls; inspect narrow layout and zoom/reflow.
9. **AC09 Rendering stability:** refresh at desktop and narrow sizes, compare stable content; inspect console/page errors and failed requests. Verify Tailwind-generated styles in the browser.
10. **AC10 Handoff integrity:** save exact commands, timestamps, exit codes and evidence, source-preservation check and SHA-256 baseline (no Git at entry), update status and template-based report; review PENDING. No next phase implementation.

Scientific numerical tests and backend API/performance checks are not applicable to this UI-only phase; they must not be represented as passed scientific validation.

Final outcome (2026-09-11): AC01-AC10 PASS, independent review PENDING. See phase-reports/phase-01-report.md for exact evidence. The 320 CSS-pixel browser case verifies narrow reflow; no broad accessibility certification is claimed.
